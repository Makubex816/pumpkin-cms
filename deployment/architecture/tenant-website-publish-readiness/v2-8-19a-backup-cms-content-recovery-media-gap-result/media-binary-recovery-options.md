# Media Binary Recovery Options

## Option 1: Operator Provides The 9 PNG Files

Preferred non-live path. The operator supplies the 9 expected filenames into a future approved intake folder outside the repo. A later phase validates names, sizes, hashes if available, dimensions, and visual fit before source integration.

## Option 2: Read-only Azure Blob Recovery Approval

The backup's blob inventory says the 9 blobs existed in Azure Blob Storage during a prior live-readonly inventory. A future phase may request explicit read-only binary retrieval approval using RBAC/session access without keys, connection strings, SAS, protected config, or secret output.

## Option 3: Public Media URL Verification Approval

The metadata includes public media URLs. A future phase may request explicit approval to check or retrieve those URLs. This phase did not perform live URL checks.

## Option 4: Recreate Assets

If binaries cannot be recovered, owner-approved replacement images can be produced or supplied. This requires new owner approval for visual fit, usage rights, alt text, and page placement.

Do not copy random images into production. Do not commit image binaries unless a later owner-approved implementation phase explicitly allows it.
