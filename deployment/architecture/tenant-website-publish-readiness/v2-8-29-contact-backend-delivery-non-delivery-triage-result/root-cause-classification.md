# Root Cause Classification

## Primary Classification

`api_acceptance_without_persistence`

The static compat endpoint can return `200 ok:true` after validation without writing the entry to Pumpkin API. This is explicitly true for the default dry-run/no-email path.

`api_generates_entry_id_only_no_storage`

The entry ID is generated by `buildFormEntry` before delivery. It is a response identifier unless the `pumpkin-api` forwarding path persists it.

`notification_delivery_not_admin_inbox`

Graph delivery, if active, sends email and returns success after Graph `202`, but it does not write to the Admin `FormEntry` read model.

## Conditional Classifications

`production_provider_binding_missing`

If Admin persistence was intended, production needs the static function to resolve to `pumpkin-api` mode and have approved Pumpkin API URL/API key binding. V2.8.29 did not inspect protected app settings, so this remains a required operator-confirmed binding fact.

`admin_inbox_reads_different_provider`

If production actually used `pumpkin-api` mode and received a successful API response, then the Admin not-found result would imply Admin is reading a different Pumpkin API backend/provider or tenant context. Source alone cannot prove or disprove this without approved environment/provider mapping.

`local_admin_not_connected_to_production_backend`

If the operator checked a local Admin instance or an Admin instance configured to a non-production Pumpkin API, production data would not appear. V2.8.29 did not inspect Admin runtime config.

`backend_delivery_requires_protected_config`

Both Pumpkin API persistence and Graph delivery require protected provider/app settings for real delivery. V2.8.29 did not read them.

## Not Primary

`tenant_site_form_id_mismatch`

The accepted entry ID and source constants align on `ice-rink-rentals` and `default-quote-request`. No source-level tenant/form mismatch explains the missing Admin row.
