# Screen By Screen Builder Spec

Each screen should show short helper text, safe examples, inline validation, and a clear "stop and ask for help" callout.

| Screen | Purpose | Key fields | Helper text | Validation rules | Stop and ask for help | Output files affected |
| --- | --- | --- | --- | --- | --- | --- |
| Welcome / Before You Start | Set expectations and hard stops. | package mode, user role, checklist acknowledgement | You will create a local import package, not launch a site. | user must acknowledge no secrets and no external changes | if asked to deploy, change DNS, send email, or index | draft session metadata |
| Tenant Identity | Establish tenant scope. | tenantDisplayName, tenantId, siteKey, businessType, cmsTenantSlug | Use one stable tenant identity across the whole package. | IDs match `^[a-z][a-z0-9-]{2,63}$`; display name 2-120 chars | if another tenant name appears | `manifest.json`, `tenant.json`, page scope |
| Domains And DNS | Capture public domains and owners. | primaryDomain, wwwDomain, mediaDomain, DNS owner, stagingHostname | Enter public domain names only; this does not change DNS. | domain format; no localhost/private/staging as production domain | if DNS record values must be changed now | `site.json`, `owner-contacts.json` |
| Deployment Profile | Select the intended deployment shape. | deploymentProfile, profile notes, profile owner | Choose the profile that operators will later validate. | profile ID exists in registry; requirements acknowledged | if unsure which profile applies | `site.json`, `manifest.json` |
| Pages And Routes | Build launch route allowlist. | approvedRoutes, forbiddenRoutes, wwwBehavior | Approved routes are pages allowed to exist; forbidden routes must stay offline. | routes normalized with leading/trailing slash; no duplicates; approved and forbidden cannot overlap | if draft/preview/old routes appear | `routes.json`, `pages/*.json`, `theme.json` |
| Page Content Placeholders | Capture page titles and safe block placeholders. | slug, route, title, seo title, description, block notes | Start with page outlines; content can be refined later. | slug route match; title length; status defaults to draft | if claims, pricing, legal statements, or another tenant content appear | `pages/*.json`, `seo.json` |
| Media / Images | Capture media manifest data. | mediaId, fileName, kind, altText, sourceStatus, publicUrl | Add approved media references; do not upload raw protected files by default. | stable media ID; alt text required; URL safety check; source status selected | if usage rights are unclear or private media URL appears | `media-assets.json`, page blocks |
| Contact Form And Recipient | Capture form routing metadata. | formId, displayName, deliveryMode, recipient, mailboxOwner, fields, consentNoticeStatus, rollbackMode | This records where leads should go later; it does not configure email. | email format; consent status selected; no passwords/tokens | if mailbox owner or recipient is unclear | `forms.json`, page blocks, `owner-contacts.json` |
| SEO / Canonical / Sitemap | Define offline SEO metadata. | canonicalHost, canonicalBaseUrl, defaultRobots, sitemapPolicy, indexingFinalGate | Production indexing remains blocked until final approval. | canonical host aligns with route; `indexingFinalGate` remains true | if asked to request indexing or submit sitemap | `seo.json`, page SEO |
| Legal / Privacy | Record review state. | privacyReviewStatus, consent status, data retention, service claims reviewer | Legal/privacy can block export or handoff. | required owner and status values | if form data or claims are not approved | `approvals.json`, `owner-contacts.json`, support packet |
| Analytics / Tracking | Record analytics decision without adding tools. | analyticsDecision, tracking tools requested, analytics owner | Analytics is a decision record only in this phase. | selected decision; no script/token values | if pixels, tags, or secrets are supplied | `approvals.json`, `manifest.json`, support packet |
| Review And Validate | Show generated file preview and run validator. | generated file list, diff preview, validation status | Review what will be exported before saving package files. | full offline validator run required | if validation reports failed, secret, or blocked | all package files, reports |
| Fix Issues | Guide the user through validator findings. | finding code, plain-language explanation, owner, fix action | Fix one blocker at a time. | errors remain blocking; warnings can be strict in operator mode | if user cannot interpret a blocker | draft fields, validation report |
| Export Package | Produce the import package folder. | export destination, overwrite behavior, package version | Export creates local files only. | block package export on critical/failed gates unless operator override policy allows draft export | if output path contains protected config or unrelated tenant files | import package folder |
| Support Packet | Export redacted troubleshooting bundle. | include validation report, owner summary, next actions | Share support packet first; do not copy raw source files by default. | no secrets; no raw protected config; no raw images by default | if secret-like value is detected | support packet files |
| Operator Handoff | Prepare manual review package. | operator owner, content owner, legal owner, form owner, rollback owner, indexing owner | Handoff is not approval to import, deploy, or index. | all owner fields present; final hard stops shown | if any owner is missing or disagrees | support packet, approvals draft |
