# Trace And Correlation Plan

Status: planned only.

Required identifiers:

- `requestId`: unique per API response, generated by future API runtime;
- `correlationId`: shared across handler, service, provider, and response for a single request;
- `tenantKey` and `siteKey`: normalized request scope;
- fixture correlation IDs: preserved inside `data.traceIds` and metadata where applicable.

Rules:

- no trace field may contain secrets, credentials, auth material, protected config values, raw customer private data, or connection material;
- errors must include request and correlation IDs;
- service/provider logs in future implementation must log IDs and route names only, not payload contents that may include sensitive values;
- trace route `/api/admin/audit-jobs/traces` must support bounded filtering and pagination;
- Admin should display correlation/request IDs as diagnostic context only.

V2.9.6 combined fixture trace baseline:

- trace entries: `107`;
- blockers: `0`;
- warnings: `1`;
- next gates: `2`.
