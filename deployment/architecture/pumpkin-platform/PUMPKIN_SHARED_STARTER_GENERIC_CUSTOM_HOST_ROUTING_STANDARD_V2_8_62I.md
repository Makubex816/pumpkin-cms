# Pumpkin Shared Starter Generic Custom-Host Routing Standard V2.8.62I

Every custom host served by the shared starter must resolve through an explicit tenant-generic mapping containing tenant ID, one or more normalized hosts, fixture/content source, and form mode. Unknown hosts must never be accepted as tenant parity merely because a generic fallback renders.

Before deployment, local Host-header tests must prove apex, WWW, home, representative content routes, contact, noindex behavior, and form mode. Cross-tenant tests must prove existing host mappings are unchanged. Source must not duplicate tenant fixtures or hard-code tenant behavior outside the route registry.

When a mapping is absent, the correct readiness result is failed closed. Repair requires owner approval, focused tests, build/package validation, an exact-path source commit, and the explicitly approved deployment count. Hostname binding and TLS occur only after the deployed host route is proven.
