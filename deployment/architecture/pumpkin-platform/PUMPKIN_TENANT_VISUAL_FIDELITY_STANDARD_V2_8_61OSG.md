# Pumpkin Tenant Visual Fidelity Standard V2.8.61OSG

When an owner supplies a trusted visual reference package, tenant visual work should follow this standard:

1. Freeze mutation boundaries before inspection. Reference packages are evidence, not import packages.
2. Inventory the archive and reject traversal, missing required files, or ambiguous roots.
3. Do not execute uploaded JavaScript. Render static evidence only after scripts are disabled or removed from the extracted review copy.
4. Record the current live baseline before repair: titles, H1s, section hierarchy, images, form behavior, and responsive layout.
5. Map reference assets to existing public tenant media by source-relative identity. Do not flatten duplicates, guess URLs, or upload without separate approval.
6. Prefer generic, data-driven renderer capabilities. Keep temporary tenant fixture content isolated and unstaged.
7. Preserve functional boundaries. Visual proof must not submit forms, mutate CMS records, or broaden deployment scope.
8. Validate locally before the approved deploy: type-check, production build, route markers, images, overflow, and network method capture.
9. Validate live at mobile, tablet, and desktop sizes. Force lazy media through the viewport and require zero broken/pending images, overflow, failed requests, and POST requests.
10. Keep screenshots, browser profiles, reference files, fixture output, and deployment archives outside the repository.
11. Produce an owner acceptance packet and require separate approval before CMS persistence, publication, or indexing.

This standard separates visual fidelity from tenant data mutation and preserves a reviewable path from static evidence to durable CMS state.
