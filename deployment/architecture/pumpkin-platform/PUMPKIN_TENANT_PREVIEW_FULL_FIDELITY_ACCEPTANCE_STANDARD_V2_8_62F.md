# Pumpkin Tenant Preview Full Fidelity Acceptance Standard V2.8.62F

A tenant preview is acceptable only when browser evidence proves the complete package intent; static reports alone are insufficient.

## Required Proof

- Every source route, redirect, title/H1 identity, internal/external/anchor/mailto/tel/download link, media dependency and alias, form instance, visible control, detail record, and article must be represented.
- Every item must be preserved, safely adapted with equivalent behavior, owner-approved as changed, or blocked. Any unaccepted blocked item fails closed.
- Forms must preserve semantic intent while having zero active POST actions, POST methods, enabled submits, runtime-key use, external email, or FormEntry creation.
- Intentional frozen-system hrefs may be preserved statically only when proof guarantees zero requests.

## Browser Matrix

- Render every route at all required viewports and assert route identity, zero horizontal overflow, zero broken/pending images, zero required-network failures, zero POSTs, and complete non-destructive interaction behavior.
- Save visual evidence outside the repository and do not substitute fallback images for required-media success.

## Operational Gate

- Packaging and deployment may begin only after every local acceptance assertion passes.
- A deployed preview still does not authorize custom domains, DNS, TLS, publication, indexing, customer-facing forms, or production launch.
