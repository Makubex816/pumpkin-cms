# Migration Dry-Run

Phase 2H-17 adds a local/offline migration dry-run that converts the file-backed Outbound Link Manager store into production-shaped candidate records. It is a schema, mapping, checksum, and rollback proof only. It never writes to a live provider, never reads protected config, and only writes generated output under ignored `.tmp`.

## Command

```powershell
node src/outbound-link-cli.mjs migration-dry-run --store .tmp/local-store-policy --profile fixtures/migration-production-provider-profile.fixture.json --rendered .tmp/render-active --out .tmp/phase-2h17-migration-dry-run --overwrite
node src/outbound-link-cli.mjs validate-migration-dry-run --migration .tmp/phase-2h17-migration-dry-run
node src/outbound-link-cli.mjs inspect-migration-dry-run --migration .tmp/phase-2h17-migration-dry-run
```

`--rendered` is optional. When omitted, the mapper synthesizes render decision candidates from the local store so the migration package still includes render-decision records.

## Inputs

- Local store directory generated by the existing scanner/store/policy commands.
- Redacted provider profile fixture with target entity/container names and credential reference IDs only.
- Optional local render output directory.

## Boundary

The command is local/offline only. It has no Azure SDK, HTTP client, CMS API client, database client, storage client, connection-string reader, process environment dependency, or protected config path reader.
