# Staging Resource Foundation Proposal

This proposal defines the future Azure staging foundation required to unblock OLM staging target/profile closure. Creation is not approved or executed in V2.3.1.

| Resource | Purpose | Maps to | Required for first OLM write | Required for stage-ready | Creation this phase |
| --- | --- | --- | --- | --- | --- |
| Azure Resource Group | Staging lifecycle, cost, RBAC, cleanup, and operator worksheet scope | `OLM_STAGING_RESOURCE_SCOPE` | yes | yes | no |
| Azure Cosmos DB for NoSQL | Real staging persistence provider for OLM records | `OLM_STAGING_PROVIDER_TYPE`, `OLM_STAGING_ACCOUNT_OR_HOST`, `OLM_STAGING_DATABASE_OR_NAMESPACE`, readback, rollback | yes | yes | no |
| Azure Storage Account / Blob Containers | Backup Center staging artifacts, Resource Registry snapshots, export evidence, runtime QA evidence bundles | Backup Center and Resource Registry staging evidence | no | yes | no |
| Azure Key Vault | Secret reference boundary for future app/provider access; no secrets in repo | Provider profile secret references only | no | yes | no |
| Managed Identity or Operator Azure CLI Session Model | Identity/session strategy for scoped staging access | `OLM_STAGING_RBAC_OR_AUTH_MODE`, `OLM_STAGING_IDENTITY_OR_SESSION_TYPE` | yes | yes | no |
| RBAC Role Assignments | Least-privilege data-plane access for first-write and readback flows | RBAC/auth mode | yes | yes | no |
| Log Analytics / Application Insights | Diagnostics for provider readiness, runtime QA, and future trace continuity | Runtime QA and operator evidence | no | recommended | no |
| Azure Budget / Cost Alert | Cost guardrail before resource usage expands | Cost and cleanup gate | no | recommended before creation | no |

## Cosmos Container Proposal

The future Cosmos provider should preserve tenant/site partitioning and the OLM production-shaped records already generated by local migration dry-runs.

| Container | Purpose | Partition key |
| --- | --- | --- |
| `outbound-links` | Canonical tenant/site outbound link registry | `/tenantKey` |
| `outbound-link-instances` | Source content locations and render usage instances | `/tenantKey` |
| `outbound-link-policies` | Tenant/site policy records | `/tenantKey` |
| `outbound-link-scan-runs` | Scanner and discovery run metadata | `/tenantKey` |
| `outbound-link-audit-logs` | Approval and action audit entries | `/tenantKey` |
| `outbound-link-render-decisions` | Deterministic render decision outputs | `/tenantKey` |
| `outbound-link-review-decisions` | Review queue decisions | `/tenantKey` |
| `outbound-link-bulk-actions` | Bulk preflight and scoped execution records | `/tenantKey` |
| `outbound-link-rollback-plans` | Rollback plans tied to action and batch IDs | `/tenantKey` |
| `outbound-link-trace-logs` | Trace continuity records with request/action/audit IDs | `/tenantKey` |

## Required Guardrails

- Do not point OLM staging at production Cosmos or production media resources.
- Do not use account keys, connection strings, SAS, or Key Vault secret values in committed docs.
- Keep `OLM_STAGING_PROVIDER_MODE` distinct from local, fake, staging-simulated, live-readonly, and production runtime modes.
- Require Backup Center pre-write evidence before the first scoped staging write.
- Require Resource Registry review before the first scoped staging write.
- Require Runtime QA evidence that no uncontrolled write calls occur outside the approved first-write batch.
